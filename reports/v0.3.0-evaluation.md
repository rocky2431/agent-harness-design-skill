# v0.3.0 evaluation report

Date: 2026-08-31

This release was evaluated with Codex CLI 0.149.0, `gpt-5.4-mini`, low reasoning,
four workers, and two fresh trials per case. Every run used a temporary `HOME`,
`CODEX_HOME`, workspace, and ephemeral session. The runner passed prompts as argument
arrays without shell interpolation.

Raw evidence:

- [`v0.3.0-behavior.json`](../eval-results/v0.3.0-behavior.json)
- [`v0.3.0-trigger.json`](../eval-results/v0.3.0-trigger.json)

## Behavior comparison

Nineteen cases were run against no Skill, the legacy `agents-best-practices` Skill,
and this release. A separate blind call graded each complete case/trial group against
the committed reference expectation. Timing and tokens are measurements; scores,
passes, evidence, and winners are model-grader judgments.

| Arm | Graded pass | Mean score (0-4) | Wins | Mean seconds | Input tokens/run | Output tokens/run |
|---|---:|---:|---:|---:|---:|---:|
| `agent-harness-design` | 97.4% | 3.684 | 15 | 21.362 | 32,585 | 692 |
| `agents-best-practices` | 94.7% | 3.526 | 7 | 21.525 | 31,746 | 725 |
| no Skill | 92.1% | 3.395 | 5 | 14.163 | 10,413 | 375 |

Eleven of 38 comparisons were ties. Relative to the legacy Skill, the candidate gained
0.158 mean score and 2.7 percentage points of graded pass rate with similar latency
and 2.6% more input tokens. Relative to no Skill, it gained 0.289 mean score and 5.3
pass-rate points, but used 213% more input tokens and 7.199 more seconds per run. The
Skill therefore earns a measurable quality improvement, but it is not free.

The candidate's only graded failure still made the requested invariant/default split.
It cited temporary local reference files, which the blind grader could not verify and
treated as invented support. The grade is retained. The runner now instructs behavior
arms not to cite Skill files, and retained evidence normalizes ephemeral roots to
`<EVAL_TMP>`; neither change rewrites the answer or score.

## Implicit discovery

Twelve cases were run twice with marker-only versions of this Skill,
`task-state-with-files`, and `agent-delegation`. A marker can appear only after the
corresponding probe body is loaded. The test therefore measures Codex implicit
selection plus compliance with the loaded probe instruction; it is not a keyword
simulation or a pure selector-unit test.

| Route class | Exact accepted selections |
|---|---:|
| Positive harness requests | 7/10 (70.0%) |
| Negative ordinary requests | 6/6 (100%) |
| Ambiguous AI feature request | 2/2 (100%) |
| Adjacent-Skill coexistence | 5/6 (83.3%) |
| Overall | 20/24 (83.3%) |

No negative or ambiguous case loaded a Skill. The four misses were three omitted
harness activations and one omitted task-state activation; no unrelated Skill replaced
the expected one. The mixed delegation-and-harness case accepts either delegation
alone or delegation plus harness design because both are valid routing choices for
that prompt.

Implicit discovery is useful but stochastic at this configuration. Explicit
`$agent-harness-design` invocation remains the reliable path when the owner needs the
Skill. This result does not justify adding a hook, router, MCP server, daemon, or
explicit-only policy. Re-run the trigger corpus after material host or model changes.

## Release decision and limits

Ship v0.3.0: explicit use improves the accepted task distribution over both baselines,
negative discovery produced no false activations, and the package remains a portable
Skill plus a Skills-only Codex Plugin.

Limits:

- two trials per case are enough to expose instability, not to estimate narrow
  confidence intervals;
- the grader used the same model family as the answer runs and was not calibrated
  against a large blinded human-label set;
- trigger probes test Codex 0.149.0 only; other hosts require separate lifecycle
  smoke tests rather than inferred parity;
- results apply to the recorded model-harness configuration, not every model, host,
  or future Skill version.
