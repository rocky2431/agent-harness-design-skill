# v0.5.0 evaluation and release record

Date: 2026-09-09. Status: source behavior verified; distribution receipt is maintained downstream.

## Scope and delivered structure

The approved seven-step plan separates general harness component design from target-model
adaptation while retaining the independent portable Skill. The entry routes new designs,
reviews, failures and migrations without imposing the full process on a short question.

- General design: a complete one-model/one-tool feedback loop and twelve component
  responsibilities, interfaces, choices, failure modes and minimum checks.
- Model adaptation: exact target selection and seven dated provider profiles, with
  API contracts, behavioral recommendations, disclosed training facts and unknowns kept
  separate. The consulting model is not assumed to be the target model.
- Historical cases: dated reasons for introducing, revising and retiring mechanisms,
  with a source-first update procedure.
- Calibration: budget diagnosis, native tool discovery, valid migration baselines,
  unknown effects, restorable evidence and isolated writes no longer inherit the old
  universal formulations.

The raw research and approved plan remain in
[RESULT.md](research/2026-09-09-general-and-model-specific/RESULT.md).

## Configuration and evidence boundaries

Real Skill trials use Codex CLI 0.153.4, gpt-5.6-sol, low reasoning, fresh temporary
homes/workspaces and ephemeral sessions. Plugins, memories, hooks and apps are disabled;
the host uses its read-only sandbox. Candidate runs load the actual Skill copy and only
its relevant references. Completed commands referencing that copy are retained without
command output; these establish requested reads, not attention or comprehension.

The original v0.4.0 baseline was restored from
`88aff97c0b33b9da0a39e9faf773a11eaf7739ae`; no-Skill is a separate comparison arm.
The selected corpus includes new model/protocol cases and existing negative, migration,
recovery and calibration regressions. These are targeted acceptance cases, not a held-out
estimate of general performance. The shipped corpus has 37 behavior cases in total.

Blind model grades are judgments, not environment proof. The grader uses the same
model family, rotates anonymous answer labels and has expected-output criteria. Residual
self-preference and order bias remain possible; concrete answers must be reviewed.

[ZCode probe](../eval-results/v0.5.0-zcode-probe.json): ZCode CLI 0.16.5 selected
GLM-5.3 at the Coding Plan provider, but exited with a process error before a final
answer. Its cause was not established. This is a failed availability probe, not a
successful evaluation or evidence of GLM protocol/optimization behavior. The earlier
[v0.4.0 report](v0.4.0-evaluation.md) used GLM-5.2 and is not directly comparable.

Do not interpret those means as a demonstrated general improvement. Cases share topics,

[initial behavior evidence](../eval-results/v0.5.0-preclarification-behavior.json).

Three initial candidate answers received score 2:

- Case 25, trial 1 correctly rejected deleting all scaffolds and proposed measured
  ablation, but omitted the explicit non-monotone drift/stopping-regime distinction.
  The final entry and adaptation method restore that distinction.
- Case 29, trial 2 handled pending-effect reconciliation well, but did not clearly
  select the session recovery path or state how current ownership/corrections survive.
  The state reference now asks for those decisions without requiring every design to
  enumerate all possible recovery implementations.
- Case 30, trial 2 gave correct DeepSeek V4 field/effort advice but omitted the public
  source and documented-versus-tested qualification. A subsequent six-case check
  reproduced that citation omission. The final entry explicitly requires primary-source
  attribution and checked date for specific model/API claims, plus untested boundaries.

A separate content review also replaced the leftover claim that everything outside the
hard core was merely a default: provider interface contracts bind within their scope.
That one-sentence intermediate correction was tested in
[12 behavior answers](../eval-results/v0.5.0-contract-clarification-behavior.json): all
executed, candidate 5/6 graded passes, v0.4.0 6/6, with the repeated case-30 omission.
This intermediate snapshot is not the release candidate.

## Independent forward-test

An independent agent answered a DeepSeek V4 adapter review and a minimal document-agent
design. It selected the target DeepSeek profile despite the consulting OpenAI model,
identified loss of reasoning_content and the xhigh-to-high mapping, and proposed a
single-loop read-only document agent without mandatory persistence or subagents.
It read SKILL.md, model-adaptation.md, models/deepseek.md, architecture-guide.md,
failure-visibility.md and trust-tools-and-effects.md and reported no navigation problem.
It also checked the DeepSeek primary documentation. This tests useful guidance and
navigation, not a live target API or deployed document agent.

## Deterministic checks

The existing installer exercises all six destination layouts, update backups, doctor
and uninstall in temporary homes. It does not establish all six hosts' live discovery.
A new graph check verifies that every packaged reference is reachable from SKILL.md
and every local link remains inside the Skill and resolves. A missing-reference
counterexample was rejected. A focused runner test verifies that only completed,
successful, Skill-scoped commands are retained and their contents are not copied.
The Skill validator and Python compilation are also part of release verification.

## Target-system coverage

All seven profiles are primary-documentation-supported guidance checked on the stated
date. No experiment in this release directly establishes optimization gains for Astra,
Fable, Gemini, DeepSeek, Kimi, GLM or Qwen target harnesses. Each profile supplies concrete
compatibility and behavioral checks and explicitly marks those target trials unverified.
Required protocol fields are not an optional optimization; repairing a deliberately
invalid baseline cannot establish an intelligence gain. Undisclosed training causes
remain unknown.

Distribution-package verification will be recorded in the downstream Marketplace
release receipt, which can refer to the final upstream commit without a circular pin.

## Final focused results and acceptance

[Final behavior evidence](../eval-results/v0.5.0-behavior.json) contains 16 completed
answers and 8 completed blind grades. The final candidate passed 8/8 graded answers
(mean 3.25/4); v0.4.0 passed 6/8 (mean 2.875/4). The sample is targeted and small;
this supports the regression decision, not a general performance claim.

Both final DeepSeek answers now cite the primary documentation and date. Both recovery
answers preserve user corrections and reconcile the original pending operation; one
explicitly distinguishes valid native continuation from a fresh handoff. Both migration
answers reject automatic wholesale removal and require measured ablation.

Remaining grader comments are retained, not erased: some answers do not enumerate all
three recovery methods or explicitly name non-monotone drift despite choosing a valid
recovery/ablation approach. The medium→high and max→max mapping is documented in the
linked DeepSeek source, although some grader comments call it outside the short expected
answer. An effort-setting recommendation is still not evidence of an optimization gain.
These limits are reasons to inspect concrete answers, not to replace the rubric or
claim perfect reliability.

|---|---|---|
| A1: basic read-only agent | Initial case 28, two trials; independent forward-test | Pass for Skill design guidance; no mandatory planner, subagents or persistent database |

Source checks cover 35 unit tests, Python compilation, Skill validation, reference
reachability and the rejected missing-link counterexample. [Final discovery](../eval-results/v0.5.0-trigger.json) made 12/12 accepted selections
(one trial for each positive, negative, ambiguous and coexistence case). Both final
evidence files match the released Skill digest. All host claims remain scoped:
installer layouts are checked for six hosts; real Skill behavior is measured on Codex.

## Release decision

Release 0.5.0 for the approved structural and content improvement, with the evidence
limits above. Keep documented provider guidance distinct from measured benefits. Retain
all initial/intermediate failures and snapshots; do not describe the release as a
universal quality or speed improvement. Publishing the source and distribution package
does not update already-installed user copies.

The downstream receipt is
[Marketplace 0.5.0 release verification](https://github.com/rocky2431/Excellent-skill-Marketplace/blob/main/docs/agent-harness-design-0.5.0-release.md).

## Post-push platform correction

The first published commit, fe80584aec1606297ef52dbd60706fca0c016912 (tag v0.5.0),
passed Linux and macOS CI but exposed two new-check portability defects on Windows:
a default-codepage read of UTF-8 references, and a scoped-command match that missed
mixed path separators. The follow-up explicitly reads UTF-8 and normalizes separators
for matching while preserving command text. Native, POSIX and mixed Windows command
paths are covered by the focused check. The initial failure remains visible in
[CI run 34303922732](https://github.com/rocky2431/agent-harness-design-skill/actions/runs/34303922732).

The Skill tree and plugin payload are unchanged, so the existing tag remains immutable
and the Marketplace can pin the corrected source commit at the same plugin version.
Prompts, grading and macOS command evidence are unchanged; only the affected deterministic
checks are rerun. Final cross-platform CI is linked from the downstream release receipt.
